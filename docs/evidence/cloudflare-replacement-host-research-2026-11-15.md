# Standalone host replacement research — 2026-11-15

Primary documentation checked on this date; local Stow/Vault integration source inspected. Recommendations are design inferences, not tested replacements. No deployments, credentials, inference or product-code changes. Scope: one team, one Linux host initially; no automatic multi-host failover claim.

## Bounded component mapping

| Cloudflare component | Recommended initial replacement and evidence |
|---|---|
| Workers HTTP/static/SSE | Bun controller behind Caddy TLS/static/reverse proxy. Bun serves streaming `Response`s; disable idle timeout specifically for SSE. Caddy immediately flushes `text/event-stream`; avoid indiscriminate `flush_interval -1`, which also changes upstream cancellation on disconnect. [Bun server](https://bun.com/docs/runtime/http/server), [Caddy proxy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy), [TLS requirements](https://caddyserver.com/docs/automatic-https). |
| Durable Objects/storage | Private local SQLite through `bun:sqlite`, plus explicit per-workspace serialized execution. WAL permits concurrent readers but only one writer and requires same-host shared memory. Keep transactions short, handle busy results, and test checkpoint/disk-full behavior. This is not distributed ownership. [Bun SQLite](https://bun.com/docs/runtime/sqlite), [SQLite WAL](https://sqlite.org/wal.html). |
| Lifecycle/DO alarms | Durable SQL jobs/outbox table and controller scheduler, startup overdue sweep, retry/backoff and ownership generation. Atomically commit accepted work, accounting hold and wake record before acknowledging. systemd restarts the scheduler; it does not make an in-memory timer durable. |
| Cron Triggers | systemd calendar timer invokes a bounded sweep. `Persistent=true` catches missed calendar activation after downtime; it does not replay every missed interval or restart an already-active service. Job-specific dedupe and catch-up rules remain SQL/application responsibilities. [Timers](https://www.freedesktop.org/software/systemd/man/latest/systemd.timer.html). |
| Containers | Rootless Podman, digest-pinned image, fixed mounts/network policy and CPU/memory/PID limits; systemd/Quadlet supervision requires cgroup v2. Keep Podman management inaccessible to agent containers: its API permits arbitrary execution as the service user. Rootless alone is not a VM isolation guarantee. [Run controls](https://docs.podman.io/en/latest/markdown/podman-run.1.html), [Quadlet](https://docs.podman.io/en/stable/markdown/podman-systemd.unit.5.html), [API boundary](https://docs.podman.io/en/latest/markdown/podman-system-service.1.html). |
| R2 archives | Trusted Stow archive service on controller-private disk, separate from agent-writable Workspace; retain encrypted archive/manifest validation. Qualify required object operations instead of assuming complete R2 equivalence. Same-host storage survives container replacement, not host-disk loss: define an independently recoverable backup destination. |
| Registry | Optional CNCF Distribution with filesystem storage, TLS/auth and retention/GC policy. For one host, deliver a verified saved OCI/image archive and `podman load`; inspect expected image identity and run with pulling disabled. No compulsory registry or root-filesystem `import`. [Load semantics](https://docs.podman.io/en/latest/markdown/podman-load.1.html), [Distribution configuration](https://distribution.github.io/distribution/about/configuration/). |
| Wrangler/deployment | Versioned release directory/image, schema migrations, systemd units, readiness checks and rollback policy. Pre-pull/load images; bound startup and stop deadlines. Quadlet supplies service generation, not application migration safety. |
| Logs/analytics | Structured journald logs with rotation/redaction; optional OTLP Collector for metrics/traces/export. Keep authoritative usage/accounting receipts in SQLite, independently of sampled/lossy telemetry. [Collector](https://opentelemetry.io/docs/collector/). |
| Rate-limit binding | Controller token bucket keyed by authenticated identity; bounded persisted admission/usage controls in SQL. Trust forwarded client identity only from the configured proxy. Caddy ignores incoming forwarded values by default; explicitly scope trusted upstream proxies if added. Optional NGINX provides keyed leaky-bucket request limits, but is not required for the Caddy baseline. [Caddy headers](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy), [NGINX limits](https://nginx.org/en/docs/http/ngx_http_limit_req_module.html). |
| Optional D1 | Migrate used tables/queries to private SQLite, preserving schema/version/transaction contracts; not a new service by default. Use SQLite backup API or `VACUUM INTO` for consistent live backups, then encrypt/publish with Stow. A raw live database-file copy is not the recovery protocol. [Backup methods](https://sqlite.org/backup.html). |

## Preserve the existing primitives

Local [Stow identity/readiness validation](/Users/ladmin/WebProjects/cf-opencode/stow-workspace.ts) binds root, registry, bucket and fresh loopback credentials. [Control startup](/Users/ladmin/WebProjects/cf-opencode/control-server.ts) already launches the registered Workspace. Reuse these contracts; Stow does not replace scheduler ownership or authorization.

[Vault](/Users/ladmin/WebProjects/cf-opencode/vendor/chester-hill-solutions/vault/src/vault.ts) accepts a ciphertext store; its [encryption](/Users/ladmin/WebProjects/cf-opencode/vendor/chester-hill-solutions/vault/src/encryption.ts) derives workspace AES-GCM keys using HKDF. Replace the DO-backed store with SQLite. Load the master key through systemd credentials, not a broadly inherited environment; keep key recovery separate from ciphertext backups. [Credential delivery](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html).

## Required acceptance guarantees

Fence ownership before replacement dispatch; a lease expiring does not prove old execution stopped. Persist lifecycle intent, runtime identity, cancellation and reconciliation receipts. Podman stop escalates TERM to KILL after its timeout; additionally verify container exit and descendant/cgroup termination before claiming stopped or releasing holds. systemd `KillMode=control-group` covers the unit's remaining processes, not arbitrary escaped work. Preserve ambiguous provider cost/external effects as unknown. Test controller death, host reboot, stale jobs, failed backups, missing keys and failed stops. [Podman stop](https://docs.podman.io/en/latest/markdown/podman-stop.1.html), [systemd kill](https://www.freedesktop.org/software/systemd/man/latest/systemd.kill.html).
