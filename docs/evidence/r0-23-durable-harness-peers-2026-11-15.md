# Durable harness peers — 2026-11-15

Research only: current official documentation and selected source were read; no external runtime tests, deployments, credentials or inference calls. This supplements the earlier Cloudflare comparison, not a new benchmark. Aboiteau's current implementation is assessed separately by the parent review.

**Finding:** durable control, recovery and an owner-operated cloud deployment are already substantial peer capabilities. Exo is the closest architecture peer here. Aboiteau's comparison should demonstrate its integrated recovery/operator/accounting behavior; it should not sell those broad categories as exclusive.

1. **OpenCode already supplies a durable loop in Cloudflare.** Documented: OpenCode owns its loop, transcript, tools and session recovery; `OpenCodeHarness` adds Durable Object SQLite storage and lifecycle wakes. Session events can be consumed live or replayed from a durable log. Idle runtime closure retains durable state. [Official integration](https://developers.cloudflare.com/agents/harnesses/opencode/).

2. **OpenCode overlaps submission and operator controls.** Inspected source: enqueue schedules a wake before prompting, uses operation-derived message identity, and supports queue versus steer delivery. Withdrawal cancels queued entries or interrupts running work. Permission state and permission-related events are exposed. Aborting a wait does not itself cancel work. These are source findings, not exercised guarantees. [Harness source](https://github.com/cloudflare/agents/blob/main/packages/agents/src/harness/opencode/harness.ts), [public types](https://github.com/cloudflare/agents/blob/main/packages/agents/src/harness/opencode/types.ts).

3. **Pi makes crash and replay semantics explicit.** Documented: Pi owns durable inbox/task/transcript state, stable-operation deduplication, follow-up queueing, steering and recovery. A crashed model request can repeat; tools marked safe may replay, while interrupted unsafe tools return an interruption result. Recovery attempts are bounded. Its documented current limitations include no tool-approval step and delayed abort when a tool ignores its signal. `maxTurns` is a tool-round bound, not a monetary cap. [Pi integration and limitations](https://developers.cloudflare.com/agents/harnesses/pi/).

4. **Think includes persisted approvals and tool recovery policy.** Documented: Think provides a loop and context/session management above AIChatAgent, with durable submissions and injected model selection. Inspected `ThinkHarness` persists approval-requested tool state, applies approval callbacks, and distinguishes tool rerun policy from reporting interruption; its default recovery policy is report. The inspected implementation rejects steer rather than silently providing it. Applications still need correct surrounding job and external-side-effect semantics. [Think overview](https://developers.cloudflare.com/agents/harnesses/think/), [harness source](https://github.com/cloudflare/agents/blob/main/packages/agents/src/harness/think/harness.ts), [tool policy source](https://github.com/cloudflare/agents/blob/main/packages/agents/src/harness/think/tools.ts).

5. **Generic accountability and approval controls are not unique.** Documented experimental Think Actions provide a durable settled-result ledger keyed by action/name/key, per-turn permission grants, human approval and structured replies. The documentation limits its side-effect claim to the happy path; this is not evidence of universal exactly-once external execution. Correct business keys and reconciliation after an ambiguous remote acknowledgement remain application concerns (inference). [Think Actions](https://developers.cloudflare.com/agents/harnesses/think/actions/).

6. **Full Linux is a composition option, not an Aboiteau-exclusive capability.** Documented: a durable agent can use a separate Linux sandbox for shell/files. Cloudflare also documents workspace save/restore independently of harness choice. Filesystem snapshots do not preserve process memory or running processes. Consequently compare a complete harness-plus-sandbox system with Aboiteau, not only Workerd-local tools. [Agents sandbox tools](https://developers.cloudflare.com/agents/tools/sandbox/), [workspace save and restore](https://developers.cloudflare.com/sandbox/files/save-and-restore-a-workspace/).

7. **Exo is the closest control-plane/recovery architecture peer.** Documented: its Cloudflare adapter combines a Rust/Wasm runtime, per-thread SQLite Durable Object turn coordination, shared account state/encrypted vault, R2 objects and a separate Linux sandbox. Acceptance queues work and a recovery alarm before acknowledging it. Model calls may repeat; ambiguous tool outcomes fail instead of blindly replaying. File/Git checkpoints do not preserve live processes. It supports basic/Codex harnesses and Responses-compatible models; OpenCode drop-in compatibility was not established. [Official Exo integration](https://developers.cloudflare.com/agents/harnesses/exo/).

8. **Exo's overlap is visible in implementation, while cost equivalence remains unverified.** Inspected pinned source has principal-aware idempotency receipts and queued/cancel/suspend/resume control; Cloudflare recovery hooks, sandbox identity checks, snapshot-before-stop and restore, plus externally applied provider proxy headers with sandbox internet disabled. The encrypted-vault description is documented; its cryptographic implementation was not audited. Credential injection is a provider-policy mechanism, not a proof of universal secret safety. No equivalent or missing per-turn monetary admission-hold/settlement/unknown-cost/operator-reconciliation contract was established by this bounded inspection. Do not infer absence or uniqueness. [Stored coordinator](https://github.com/exoharness/exo/blob/1eeab021a854dc8db502d82b9fe656cbaf044671/crates/exoharness/src/turn_coordinator/stored.rs), [Cloudflare provider](https://github.com/exoharness/exo/blob/1eeab021a854dc8db502d82b9fe656cbaf044671/exoharness/cloudflare/src/provider.ts), [sandbox](https://github.com/exoharness/exo/blob/1eeab021a854dc8db502d82b9fe656cbaf044671/exoharness/cloudflare/src/sandbox.ts), [network policy](https://github.com/exoharness/exo/blob/1eeab021a854dc8db502d82b9fe656cbaf044671/exoharness/cloudflare/src/network.ts).
