## Conditions and limits

- Two authored diagnostic tasks, L1 and Q1, one repetition per arm. This is a
  wiring/qualification smoke, not representative coding accuracy, a winner,
  latency percentiles, or C0/G0 closure.
- Workspace/container and SDK task state were fresh. The Worker and some
  coordinator code were primed by model-free qualification/preparation;
  provider prompt-cache state was not instrumented. Do not call every layer cold.
- Exact endpoint, model, temperature0, 4096-token output bound, pinned native
  image/resource request and task/fixture Git bases were shared. The baseline
  uses OpenCodeHarness/Workerd plus its Linux tools; Aboiteau uses actual
  Conversation orchestration plus native OpenCode. Tool schemas, system prompts,
  SDK execution substrate and policies differ. The matched stratum stays unrated.
- The native staging build profile allows shell work in its owned VM while
  preserving product hard denials. The baseline's arbitrary owned-VM shell is
  still broader. No unknown permission request was approved automatically.
  Production permission policy and deployment were unchanged.
- End-to-end time covers dispatch, startup/coding, snapshot, stop and independent
  grading; it is not pure model latency. All four finished inside the 600-second
  per-cell bound. Portable recovery, fault controls and provider-side stop remain
  unqualified. Native cancellation previously observed descendant work after
  caller abort; container-stop observations are separate.
