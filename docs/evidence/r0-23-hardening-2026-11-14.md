# R0-23 baseline hardening — v3

Evidence only. Scheduling and gate status remain in the
[canonical plan](../roadmap.md).

The audit covered `bench/comparison/baseline/` under the pinned SDK/Workerd
configuration: production-audit clusters 2 (concurrency, separate read-only
review) and 3 (reliability). It did not audit the production service, native
isolation, provider billing or comparative coding quality.

Nine defects were reproduced and repaired. The concurrency reproductions used
the real actor/plugin source with deterministic platform/SDK boundaries. The
tracked regressions exercise the actor's extracted runtime orchestration, real
Linux adapter and real provider request/parser code with simulated failures.

Paths in the table are relative to `bench/comparison/`. Full pre-fix failures,
final observations, source hashes and commands are retained in the
[machine-readable receipt](r0-23-hardening-2026-11-14.json).

Final checks: **37 tests, 155 assertions, both TypeScript projects, ten
base/reference oracle discriminations, offline bundle and local Workerd smoke
pass**. The SDK smoke exercises the same runtime wrapper as the task actor,
five simulated tools, six mocked HTTP/SSE model requests, concurrent SQLite
admission, retained cleanup receipts and disabled alarms. Local state is removed.

The [v3 manifest](../../bench/comparison/protocol.freeze.json) identifies the
checked code. [V1](../../bench/comparison/protocol.freeze.v1.json) and
[v2](../../bench/comparison/protocol.freeze.v2.json) identities and observations
remain separate. No deployment, external inference or scored comparison ran.

Unverified: native cancellation/descendant behavior, native actor recreation and
fault injection, real-provider interoperability/cancellation/billing, snapshot
quiescence, representative workload coverage and paired operating cost. The
adapter's strict uncertainty policy differs from upstream defaults and remains
part of the product stratum. The matched stratum, C0 and G0 remain open.
